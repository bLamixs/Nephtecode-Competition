> **Хакатон «НефтеКод 2.0»**  
> Промышленная мультиагентная система (MAS) рекомендательной поддержки оператора установки гидроочистки ГОДТ 24-2000 и атмосферно-вакуумной трубчатки (АВТ). Обеспечивает баланс между качеством товарного топлива (Евро-5), энергоэффективностью и ресурсом оборудования с безусловным соблюдением ограничений безопасности.

---

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Запуск БД (TimescaleDB)
```bash
docker-compose up -d timescaledb
```

### 3. Инициализация БД
```bash
make db-init
```

### 4. Загрузка и конвертация данных
```bash
make load-data
```

### 5. Запуск пайплайна по сценариям
```bash
make run              # normal: штатный режим
make run-risk         # risk: превышение серы (выдача рекомендации)
make run-missing      # missing: сбой датчиков / устаревшие анализы (отказ)
make run-no-solution  # no_solution: технологический тупик (отказ)
```

### 6. Запуск веб-дашборда оператора
```bash
make dashboard
```

## 🧪 Сценарии работы системы

| Сценарий | Технологическая ситуация | Поведение мультиагентной системы | Статус |
| :--- | :--- | :--- | :--- |
| **`normal`** | Стабильный технологический режим. Сера в норме ($\le 10$ мг/кг), риски низкие. | Система **не выдает избыточных управляющих действий** оператору, фиксируя штатное состояние. | `NO_RECOMMENDATION` |
| **`risk`** | Нарастающий тренд серы в товарном ДТ ($S > 9.5$ мг/кг) при тяжелом сырье. | Выдача **упреждающей рекомендации**: снижение температуры $T_6$ реактора на $-3.3^\circ\mathrm{C}$ для стабилизации серы на уровне $7.5$ мг/кг при росте выработки на $+63$ м³/ч в зеленой зоне риска. | `RECOMMENDED` |
| **`missing`** | Сбой телеметрии КИП (пропуски $> 30\%$) либо устаревание анализов ЛИМС ($> 120$ мин) при оффлайн ПАК. | **Мотивированный отказ**: «Недостаточно данных для безопасного управления». Система переводится в безопасный режим наблюдения. | `NO_RECOMMENDATION` |
| **`no_solution`** | Технологический тупик: одновременное превышение серы и высокий риск закоксовывания катализатора. | **Мотивированный отказ**: «Нет допустимого решения». Все сгенерированные альтернативы нарушают технологические ограничения безопасности. | `NO_RECOMMENDATION` |

## ⚠️ Технологические допущения и принципы безопасности

1. **Исторические данные**: Прототип обучен и протестирован на синхронизированных 10-минутных срезах установок АВТ и ГОДТ 24-2000 за период 2023–2026 гг.
2. **База данных**: В промышленном контуре используется связка **PostgreSQL + TimescaleDB** (Docker), в локальном демонстрационном режиме поддержан прозрачный fallback в SQLite (`output/recommendations.db`).
3. **Безусловное Veto безопасности**: Жёсткие технологические ограничения (содержание серы $\le 10.0$ мг/кг по ГОСТ 305-2013, предельные температуры печи $T_{55} \le 386^\circ\mathrm{C}$ и реактора $T_6 \le 380^\circ\mathrm{C}$, баланс долей смешения $= 100\%$) обладают абсолютным приоритетом над экономической выгодой.
4. **Иерархия достоверности качества**:
   > **ЛИМС (лабораторный факт)** $>$ **ПАК (оперативный замер)** $>$ **ВАК (аналитическая кинетическая модель)**
5. **Отсутствие заглядывания в будущее (No Time Leak)**:
   - Временная синхронизация выполнена строго по `merge_asof(direction='backward')`.
   - Валидация моделей построена на строгом Holdout-сплите по времени (обучение: 2023–2025 гг., валидация: 2026 г.) без случайного перемешивания (`no shuffle`, `no sample(frac=1)`).
